# firepaas v1.2 实现纪要

> 状态：代码已覆盖 A–F 的主要路径，但**不满足发布门禁**（2026-08-31）。
> 本文只记录仓库当前可见实现与证据边界；“存在测试/脚本”不等于本次已运行通过。

## 实现范围

### A — Runtime capability（ADR-0023，已接受）

- agent proto 暴露 protocol version、feature IDs 与 snapshot compatibility key；
  `internal/capabilities` 维护稳定 feature ID。
- nodemanager 将能力投影到 PG；scheduler 对启动能力先做硬过滤，API 对
  logs/exec/cp 做 action-time 检查。
- deployment 的 required features 由平台语义推导，客户端不能伪造内部能力。
- `/v1/capabilities` 按能力返回 eligible 节点，不把节点能力并集解释为集群保证。

### B — One-shot secret（ADR-0024）

- hypeman sibling checkout `a5b1f92` 提供 guest gate 与 one-shot 文件投递；
  firepaas 使用 execution-bound lease、同步投递和 ACK 状态机。
- `FIREPAAS_SECRET_INJECTION=oneshot` 才允许上报 `secret.oneshot.v1`；unsafe/off/
  未知模式 fail closed。接收过 secret 的 execution 禁止 pause/standby/memory snapshot。
- migration 0021 追加“每个 machine/execution 仅一条历史 lease”约束；若已有重复
  历史会明确失败，不静默删审计记录。

### C — Logs / Exec / Cp（ADR-0025，已接受）

- agent gRPC、REST 和 fpctl 已接入 logs、exec 与单普通文件 cp，并绑定
  machine/execution fencing。
- streaming RPC 受 control-plane mTLS 身份校验；会话并发、字节、空闲和总时长
  有界，换代后已建立会话由 execution watcher 终止。审计只记录 caller、目标、
  命令/路径摘要、字节和结果，不记录正文/stdin/stdout/env。
- Exec `operation_id` 必填且在 guest 启动前记录；重复 ID 明确拒绝（无 reattach）。
- TTY 由 guest PTY 支持；REST/CLI 只支持初始尺寸，不提供后续交互式 resize。
  hypeman 当前不支持通用 exec signal；Signal 帧返回明确不支持，不能计为已交付。
- cp guest agent 逐组件使用 `openat(O_NOFOLLOW)`，拒绝最终及中间 symlink；
  fpctl 下载经同目录临时文件完整校验后原子 rename，失败保留已有文件。

### D — Wait / TTL / Restart（ADR-0026，已接受）

- wait API 绑定 operation、execution 或 rollout generation，返回 reached、timed out、
  superseded 或冻结的 terminal reason。
- TTL 使用绝对 expires_at；migration 0022 追加 route-detached 阶段，先摘路由再派发
  fenced delete。
- restart policy、attempt、backoff/stable window 和 blocked 状态由 PG/control-plane
  掌权；replacement 仍重新经过 quota、placement、admission 和 secret delivery。

### E/F — 治理、事件与 GC

- disk requested capacity 已进入 scheduler、reservation 和 agent admission；项目 quota
  使用 revision/ETag CAS；API rate limit 使用 Redis token bucket，mutation/stream
  在 Redis 故障时 fail closed。
- user events 与 scheduler events 分离；事件保留期有界，敏感正文不进入 details。
- image GC 使用 PG desired roots、在途 operation roots 和 agent live roots；默认
  `dry-run`，delete 启用前仍需 watermark、在用保护和回拉验证。

## Review 修订摘要

- capability：明确启动硬过滤与 action-time 检查的边界；多节点混跑仍是门禁。
- runtime channel：stream 身份校验与资源上限 fail closed；signal 明确降级为不支持。
- secret lease：终态 lease 不可再次 claim/deliver/ACK，同 execution 不重签；不确定
  投递必须换 execution。
- lifecycle：TTL 先摘 route 后 delete；restart delay 绑定失败 execution，换代/attempt
  以 PG CAS/事务防 stale owner。
- governance/GC：跨 project 端点必须 gated；quota 读取错误和 Redis mutation/stream
  限流故障 fail closed；GC 默认 dry-run，roots 不完整时不得 delete。

## 发布阻塞、迁移顺序与回滚

1. **hypeman release 阻塞**：`go.mod` 仍以 `replace github.com/kernel/hypeman =>
   ../hypeman` 依赖 sibling checkout；`a5b1f92` 不是可发布的 semver module 依赖。
   CI tag gate 应持续阻止 release，直到发布不可变 module 版本并移除 local replace。
2. **v1.1 入口门禁 waiver 未批准**：v1.2-plan 要求的标准多节点拓扑、72h soak、
   scorecard PASS 或明确 waiver 尚未具备；当前没有已批准 waiver，不能将门禁追认为通过。
3. **migration 切片顺序风险**：0015–0020 按功能切片，review 修复在 0021/0022；
   迁移器按文件名字典序逐个事务执行。部署必须完整顺序执行到 0022，不能只挑某个
   v1.2 子版本的早期 migration 后运行新二进制。尤其 0021 会在重复 lease 历史存在时
   停止，需先人工审计处理；不得删除或改写既有 migration。
4. **rollback**：数据库列/索引保留，回滚应用时停止新 lifecycle/lease/GC 行为，
   不做 down migration；secret 不确定投递须 fenced delete 后换 execution；GC 回滚设
   `FIREPAAS_GC_MODE=off`（已删除 cache 只能重新 pull）；agent/controller/hypeman
   涉及 one-shot 时应成组回滚并先 drain secret workload。

## 尚未覆盖

- 混合版本多节点 capability 与调度；跨节点 restart、leader handover、ACK loss；
- secret 在投递前、投递后、ACK 前后的 agent/controller crash 矩阵；
- GC delete watermark、agent in-use rejection 与删除后回拉；
- 多 edge、标准 2 compute / 2 edge / 3 server 拓扑；
- 72h soak 与长期资源、reservation、operation、缓存残留观察。
