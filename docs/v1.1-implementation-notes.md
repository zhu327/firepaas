## 1. V1.1-A auto-standby（ADR-0017）

### 1.1 探针排除的实现形态（对 ADR 决策 3 的修正）

ADR 原案：把探针源段（slot 网关/veth 段，如 `10.12.0.0/16`）注入
`IgnoreSourceCIDRs`。**实现评审发现该机制在 slot 后端下有误伤**：host 侧
readiness 探针（health worker → slot IP）与 agent proxy 转发回流
（edge → proxy → slot IP）共享同一源地址段（root 侧 veth 主机地址，
10.12.0.0/16——两条路径的路由源选择相同）。按源段忽略会同时排除全部真实
流量，后果：

- busy 实例在 established 连接仍存活时被判空闲并 standby（掐断在途请求）；
- wake-on-traffic 语义退化为"每请求唤醒"。

**实现改为精确按连接排除**（`internal/agent/probeflow` + `internal/agent/standby`）：

1. 探针 dialer 在 `Control` 回调里显式 `bind :0` 固定本地端口，并在 connect
   发出 SYN **之前**把四元组登记进 registry（登记先于任何 conntrack 事件，
   无竞态）；
2. agentd 用 filtered `ConnectionSource` 包装 `autostandby.NewConntrackSource()`，
   `ListConnections` dump 与事件流均丢弃命中的连接。

策略里的 `ignore_source_cidrs` 字段保留为平台透传（app 级声明如监控拨测源
段），但**不再默认注入 veth 段**。registry 条目不使用 TTL：它在 dial 前登记，
dial 失败立即删除，并由返回连接的 `Close` 删除。因此长 keepalive 探针始终被
过滤，而连接结束后的端口复用不会误过滤真实流量。

### 1.2 standby 是可服务态的代码落点

- `store.ActiveRouteMachines`：`observed_state IN ('RUNNING','PAUSED')`
  （PAUSED backend 保留在 route 投影，readiness 冻结值；NOT_READY 入睡的实例
  edge 不路由、永不唤醒——正确语义）。
- `controller.allReady`（CUTOVER 门控）：接受 `RUNNING 或 PAUSED` +
  readiness ∈ {READY, UNCONFIGURED}——PREPARING 期间新代副本 idle 到点
  standby 不阻塞切流，首个请求承担唤醒延迟（<5s SLO）。
- 唤醒路径不变（M4.5 autoresume）：proxy `GetEndpointForPort` 遇 standby 同步
  restore + reattachSlot；唤醒计数/耗时经 adapter 的 wake observer 上报
  （`firepaas_agent_autostandby_wakes_total` / `..._wake_seconds`）。

### 1.3 装配与配置

- agentd：`standby.NewInstanceStore(set.Instances)`（类型断言 hypeman 具体
  manager 的 runtime 持久化能力，失败即降级关闭）+ filtered source +
  `autostandby.NewController`；`FIREPAAS_AGENT_AUTOSTANDBY`（默认 true）、
  `FIREPAAS_AUTOSTANDBY_MAX_CONCURRENT`（默认 4）。
- proto `MachineSpec.auto_standby`；`deployments.auto_standby jsonb`
  （protojson 固化，随 rollout 语义变更）；API `auto_standby`
  `{enabled, idle_timeout_seconds ≥5, ignore_destination_ports[]}`；
  fpctl `--auto-standby-idle N`（0=关闭）。
- controller 侧事件/指标：RUNNING→PAUSED 迁移记 `autostandby` 事件 +
  `firepaas_machine_standby_total`。

## 2. V1.1-B 镜像缓存亲和与预取（ADR-0018）

- `ServiceInfoResponse.cached_image_digests`（agent 从 ListImages 派生；
  每镜像贡献 name-digest 与 manifest digest 两种形态——OCI index 引用二者
  不同，M5 遗留的对齐策略）；按 `CreatedAt` **最新创建优先**截断（不是 LRU，
  hypeman 未提供 last-used）；`nodes.image_cache jsonb` 随 20s sync 落库。空
  快照不覆盖旧 cache：ServiceInfo 当前不能区分“确实为空”与 ListImages 失败，
  因此优先保留已知亲和信息。
- scheduler：`Request.ImageDigest` + `Node.CachedImageDigests`（集合）；
  score 增加 `WeightImage · imageMiss`。**nil 缓存视图与空集合同罚**
  （proto3 repeated 无法区分"未上报"与"空"；不罚会让未上报者永远战胜已
  缓存节点）。默认 `WeightImage=0.5`，`FIREPAAS_SCHED_WEIGHT_IMAGE` 可调
  （0 = 关闭）。亲和只出现在打分层（不过滤，新镜像永远有候选）。
- 预取：rollout PREPARING 首次对账时向 top-K（`FIREPAAS_PREFETCH_TOPK`，
  默认 3）真实 create 硬候选（pool、labels、资源、deployment anti-affinity）异步
  `PullImage`（新增 agent `ImageService.PullImage`，幂等；磁盘水位守护
  `FIREPAAS_PREFETCH_DISK_WATERMARK` 默认 0.9）。失败/超时只记
  `prefetch_failed` 调度事件，不阻塞 rollout；所有 RPC 与事件写入绑定当前
  leader reconcile context，leader 丢失即取消，任期内去重（重启重发无害）。
- R3/evacuate 重建天然吃到亲和（重建请求携带 digest）。

## 3. V1.1-C edge 流量语义（ADR-0019/0020）

- 响应头 `X-Firepaas-Machine-ID`：在 `proxy.ServeHTTP` 前预写 writer header
  （覆盖正常转发/serve-stale/403 重试全部路径，重试前按新 backend 重设）。
- 钉扎 `X-Firepaas-Pin-Machine`：eligible 集合内直选（跳过 least-inflight，
  但不豁免 hard）；不在集合 → 404 + `X-Firepaas-Pin-Error` 说明头。
- inflight：`inflightTracker`（per-machine 原子计数，请求生命周期含流式——
  `ReverseProxy.ServeHTTP` 阻塞到连接结束）；metrics 快照剔除"计数 0 且
  超 2min 未更新"的条目防泄漏。
- 选择：least-inflight + 同分随机打散（替换 round-robin 计数器）；
  `FIREPAAS_EDGE_HARD_CONCURRENCY`（默认 256）——最闲者仍超限 → 503 +
  `Retry-After`；钉扎目标超限同样 503。
- per-edge 语义（多 edge 各自计数）已在 runbook-operations 标注。

## 4. V1.1-D drain evacuate（ADR-0021）

**迁移顺序与 ADR 原案的偏差**：ADR 描述"触发换代重建 → 新代 READY 且切流 →
旧实例 delete"。实现采用 **delete → R3 换代重建**（同一编排语义，顺序相反）：

理由：现 reconcile 模型假设一台 machine 同一时刻只在一个 agent 上
（`syncObserved` 的 seen map 按 machine_id 去重；R2 "agent holds stale
execution" 会作废在途 create）。若新实例（新 execution、同 machine_id）在旧
实例存活期间落到第二个节点，两个 agent 都会上报同 machine_id——seen map
互相覆盖，R2 会误杀新代 create 或漏删旧实例。delete-then-recreate 完全复用
已验收的 R2→R3 收敛链路，无新状态机；代价是单副本 app 在删除→新代 READY
窗口内短暂不可用（ADR-0021 §4 已文档化的边界，建议副本 ≥2）。

- `POST /v1/nodes/{id}/drain` body `{"evacuate": bool}`（默认 false =
  M5.5 兼容）；`nodes.evacuate` 列持久化运维意图（ready 一并清除）。数据库
  部分唯一索引限制全局一个 active evacuate node；`evacuation_machine_id` 和
  `evacuation_started_at` 持久化当前步骤，leader 切换不会跳过等待。
- 编排：每 5s 最多推进一个 machine；active rollout 查询报错 fail closed，存在
  rollout 的 app 记 `evacuate_skip`。replacement 必须在非源 node 且
  RUNNING/PAUSED + READY/UNCONFIGURED（即 route-ready）才推进下一步；
  `EvacuateStepTimeout`（默认 5m）到期记录告警但保持同一持久步骤，绝不跳过；
  完成记 `evacuate_complete`。
- `scripts/lab/upgrade-agentd.sh` 已升级为 evacuate 版（drain+evacuate →
  等归零 → nomad restart → ready → 对账）。
- 单机实验室验收：machine 归零 + 事件 + ready 恢复（e2e-v11 D 段）；
  **多节点零停机迁移（并发 curl 0 失败）DEFERRED-MULTI-NODE**。

## 5. V1.1-E 多端口 services（ADR-0022）

- `deployments.services jsonb`（`[{name, internal_port}]`，主 service =
  第一条继承单端口语义；存量单 port 零迁移）；`port` 列保留（互为别名，
  API 层 `resolveServices` 归一：二者冲突 400）。
- proto `MachineSpec.services`；agent 侧附加 services 存 base64url tag
  （`tagServices`，主端口沿用 `tagPort`）；`GetEndpointForPort` 白名单校验
  （wantPort=0 = 旧行为；未声明端口 `ErrPortNotAllowed` → 502）。
- catalog hostidx：值演进为 JSON 数组（首元素 = 主端口；旧单数字值兼容读）。
  controller 以 hostname 聚合权威完整端口集，Redis Lua 单次替换 routes+hostidx
  并删除集合中已移除的 service route；不做逐端口 read-modify-write，故并发
  rebuild 不丢端口、service 删除不留残余。`GetRouteForPort` 区分"已声明端口"
  与"权威 miss"（未声明 → 404）。
- edge：`FIREPAAS_EDGE_EXTRA_PORTS`（逗号/区间，默认关闭）附加监听；
  按 (hostname, 请求端口) 查路由（Host 显式端口 = 主监听端口时视为主入口）；
  Director 设置 `X-Firepaas-App-Port: <internal_port>`（头缺失 = 旧行为）。
- readiness：每 machine 仍单探针（主 service），附加 service 跟随（ADR-0022
  记录的 v1.1 限制）。
- 验收：e2e-v11 E 段（双端口分别路由 + 未声明端口 404 + 单端口存量回归）。

## 6. V1.1-F 打包小项

- **rolling batch**：`deployments.strategy`（bluegreen 默认 | rolling）。
  状态机不新增状态：PREPARING 只从 active rollout 的 target deployment 计算
  per-ordinal draining；新代必须 RUNNING/PAUSED + READY/UNCONFIGURED，空
  readiness 不可切流，且 old/new route draining 使用同一判定。reconcileAppScale
  以 `cutCount + batchSize`（batch = max(1, 25%·N)）为建新上限；
  `rollingRecycleCutOrdinals` 逐批回收已切流旧代。回滚先由持久 target 切回
  from generation 并确认其全量服务，再删新代、将 from 设回 ACTIVE，故不会
  造成旧代不可立即服务。全部 ordinal 切流后 allReady → CUTOVER → COMPLETE
  （CUTOVER 只回收残余旧代）。
- **agent 指标直抓**：agentd `FIREPAAS_AGENT_METRICS_PORT`（默认关闭）在
  `FIREPAAS_AGENT_METRICS_BIND`（默认 `127.0.0.1`）上提供 Prometheus 端点。
  正式 Nomad system job 显式设为 `0.0.0.0:9464`，注册
  `firepaas-agentd-metrics`，Prometheus 用 Nomad SD 抓取；因端点无 HTTP 鉴权，
  compute 节点 ACL 必须仅允许可信 observability 网段访问 9464，绝不可公网暴露。
- hypeman `vm_metrics` 的 per-VM CPU/RSS 与 autostandby/唤醒指标可直抓。**per-VM
  slot 网卡网络指标为 DEFERRED**：slot netns 中尚没有正确的 TAP 统计采集链路，
  本版不宣称网络维度已交付，也不以归零值作为指标。原"per-VM usage 管道"方案
  废止（观测动机由 CPU/RSS 直抓覆盖，idle 动机由 V1.1-A 覆盖）。
