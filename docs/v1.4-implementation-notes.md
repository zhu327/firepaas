# firepaas v1.4 实现笔记（v1.4.0 baseline + v1.4.1/B + v1.4.2/C + v1.4.3/D 增量）

> 状态：部分实现、尚未达到 v1.4 版本级验收（截至 2026-09-01）。依据
> `docs/v1.4-plan.md` 与已接受的 ADR-0036/0037；本文描述当前工作树，不构成发布证明。
> destructive local GC 的 `FIREPAAS_LOCAL_GC_MODE` 默认值是 **`off`**；dataset CoW
> 保持关闭（不广告、明确拒绝）。

## 交付范围

### v1.4-A：Baseline Hardening

| 修复 | 实现 |
|---|---|
| snapshot delete 对 DELETING 幂等收敛 | `store.BeginSnapshotDeleteAndEnqueue`：同键在途操作幂等重放；终态（FAILED）尝试按 `-rN` 后缀重派；孤儿 DELETING（无在途操作）接受新删除。API `DELETE /v1/snapshots/{id}` 对 DELETING 返回 202 + operation_id（原 409）。`processSnapshotDelete` 以 op 行 ID 归一 agent 幂等键；并发收敛竞态按"重读后继续/已 DELETED 幂等成功"处理 |
| fork/restore 引用生命周期 | `AcquireSnapshotReference` 对已持有引用同操作幂等（不再要求快照仍 READY）；fork/rescue 终态失败路径显式释放引用；新增 `ReleaseTerminalOperationReferences` 周期回收器（lease ticker）兜底崩溃路径；delete 被 active 引用阻塞时保持可重试（requeue），不再终态 FAILED |
| capability 真值 | agentd 停止发布 `volume.dataset_overlay.v1`（CoW 未过验收）；API 对 overlay attach 明确拒绝（节点无能力 → 409） |
| DATASET_RO URL 加固 | v1.4 只接受无 userinfo/query/fragment 的 credential-free HTTPS（loopback 例外仅供 hermetic e2e）；API 侧规范化 + `source_url_digest` 摘要；agent 侧同规则复验；`redactDatasetSource` 保证下载错误正文不含 URL/host；`redact` 黑名单新增 `source_url`（operation trace 打码，摘要不受影响） |
| volume UNAVAILABLE→READY 依据 inventory | 保持并加强：`reconcileVolumeNodeState` 只在 agent ListVolumes 证实本地 materialization 后恢复 READY（本版本同时产出 integrity 观测） |

附带修复（基线门禁）：
- `store_test.go` rescue 测试 `ON CONFLICT (app_id)` 引用已删除约束 → `(hostname, port)`；
- agent dataset 下载 transport：resolver 对 IPv4 字面量返回 IPv4-mapped IPv6，`publicDatasetAddr` 无条件拒绝 4-in-6 导致 loopback 测试例外永远失败 → resolver 产物先 `Unmap()`（字面量 4-in-6 写法仍被拒绝）；
- `processDatasetImport` protojson 改 `DiscardUnknown`（持久化请求携带 `source_url_digest` 观测元数据时不得拒发导入）。

### v1.4-B：Node-local Inventory、Integrity 与 GC

- proto（向后兼容，仅新增响应字段）：`ListSnapshotsResponse`/`ListVolumesResponse` 增加
  `complete`（全量列表标志；带过滤参数不得置 true）、`observation_epoch`（agent 每次启动
  生成、不可复用）、`observation_generation`（同 epoch 内严格递增）、
  `observed_at_unix`。旧 agent 缺字段 → proto zero → 控制面只产生 UNKNOWN。
- 控制面将接受的 `(node,type,epoch,generation)` 写入 `local_inventory_observations`；同 epoch
  的旧 generation 以及已退役 epoch 的迟到响应被拒绝，agent 时间只用于合理性检查。
- 新 capability `inventory.local.v1`（agent 侧完整 List 响应填充上述元数据即发布）。
- migration 0028：`snapshots`/`volumes` 新增 `integrity`（UNKNOWN|METADATA_VERIFIED|
  CONTENT_VERIFIED|MISSING|CORRUPT）+ `integrity_observed_at`（仅新增带默认值列；回滚保留数据）。
- controller 对账（`reconcileSnapshotIntegrity`/`reconcileVolumeIntegrity`，sync ticker）：
  - 完整列表 + 产物缺席 → `MISSING` + 业务状态降 UNAVAILABLE（阻止 restore/fork/attach；不自动 LOST、不自动创建空同名卷）；
  - 产物在场 + PG 必要事实完整 → `METADATA_VERIFIED`（CONTENT_VERIFIED 需内容 checksum 重算，本版未启用）；
  - 在途 create/import（CREATING）不推导 MISSING；
  - orphan（agent 本地有、PG 无）只报告：`firepaas_local_orphan_bytes` 指标 + 去重事件；不自动删除。
- 指标：`firepaas_local_inventory_support`、`firepaas_local_integrity`、
  `firepaas_local_integrity_transitions_total`、`firepaas_local_orphan_bytes`；
  租户事件 `snapshot.integrity.missing` / `volume.integrity.missing`。
- API 门禁：fork/rescue/attach/preflight 对 MISSING/CORRUPT 明确拒绝；snapshot DTO 暴露 `integrity`。
- ADR-0036 的数据库与执行协议已实现：`local_scrub_jobs`、`local_gc_claims`，claim token
  仅保存摘要，pin 与 image claim 共用 PG 锁域；agent 通过 hypeman path-free、lock-aware
  接口执行 snapshot scrub 和 image/dataset quarantine、rollback/finalize。`off` 不扫描；
  `dry-run` 只报告候选；`delete` 仍须单节点恢复演练后显式开启。snapshot、LOCAL_RW 和
  不可重建 DATASET_RO 不进入自动删除候选。

### v1.4-C：OCI Image Prewarm、Coverage 与 Cache Pin

- migration 0027：`image_prewarm_targets`（逐节点结果）、`image_pins`
  （project+digest+selector 唯一；node:<id> / node_pool:<name>）、`image_sizes`（digest 观测大小）。
- API：`POST /v1/images/prewarm`、`GET /v1/images/coverage`、
  `POST/GET/DELETE /v1/images/pins`。按 ADR-0037，在 node-pool ACL 落地前这些端点
  **全部仅允许 root/admin**；普通 project read/write key 必须得到 403。project ID 仍用于
  PG 配额和审计，不表示租户获得节点选择或拓扑读取权限。
- controller `processPrewarm`（kind=image_prewarm）：逐目标节点 PullImage；确定性失败记
  节点 FAILED、瞬时失败 op 级重试；完成节点不重复拉取；成功后记录 `image_sizes`；
  终态携带逐节点明细 + `image.prewarm.completed` 用户事件。
- pin 准入：TTL ≤ 7d（默认）、目标节点数上限、每项目 pin 数、pinned bytes
  （Σ size × 当前 selector 命中节点数；无观测大小的 digest 拒绝 pin——先 prewarm）、
  目标节点磁盘 hard watermark（默认 0.90，env 可调）拒绝新 pin/prefetch。
- GC 联动：`PinnedDigestsForNode`（active pin + 在途 prewarm 目标，按节点作用域）并入
  image GC roots（候选计算与每次删除前重确认均含 pin roots）；过期 pin 周期回收。
- 指标：`firepaas_prewarm_targets_total{result}`、`firepaas_image_pins_expired_total`。
- fpctl：`fpctl images prewarm|coverage|pin|pins|unpin`。
- rollout 自动预取（best-effort）行为不变。

### v1.4-D：DATASET_RO 与 Restore Usability

- restore preflight：`POST /v1/snapshots/{id}/preflight`（read-only；read scope；project gated）。
  返回 locality/durability、origin node availability、integrity、memory 兼容性（结构化 +
  opaque key）、可用 restore mode、缺失 capability、blocking issues、observed_at（时点观测，
  非执行授权）。`memory` 不兼容明确 false；`auto` 只报告可否降级 filesystem。
  preflight 与实际 rescue 派发共用 `controller.DecideRestore`（结论一致性由构造保证）。
- dataset 导入：URL 规则与脱敏见 v1.4-A；spool 文件名携带 volume 与 operation 摘要；
  agent 启动清理超龄（>20min，导入授权窗口 15min）且非当前进程 active import 的残留
  （`CleanupStaleDatasetSpool`）。
- DATASET_RO 多挂载/删除引用保护/半成品不可挂载：既有实现 + store 回归测试覆盖
  （`TestDatasetMultiAttachAllowed`、`TestUnsealedDatasetCannotAttach`）。
- per-execution CoW：保持关闭（capability 不广告 + API 明确拒绝），待 hypeman 能力与
  真机 e2e 证据。

## 验证状态

本节不保留“实现完成”或历史 ALL PASS 声明：当前 changeset 尚未取得可复现的完整发布
证据。`scripts/lab/e2e-v14.sh` 是单节点 smoke，且本次仅做静态校验、**未执行**；它不能

完整 72h soak，并归档原始 observation，而不是只记录结论。

## 独立评审（code-reviewer）结论与修复

REQUEST_CHANGES → 已修复：
- P1 prewarm 绕过镜像准入：prewarm/pin（带 image_ref）现走同一 `imagepolicy.Validate`
  （digest 形态 + registry allowlist）。
- P1 MISSING volume 永久 wedge：UNAVAILABLE 允许删除（API + store）；agent
  `DeleteVolume` 对 hypeman `ErrNotFound` 幂等；回归测试覆盖。
- P2 prewarm 拉取无单次超时：每目标 `PullImage` 包 `AgentRPCTimeout`。
- P2 node-pool 权限：采用 ADR-0037 临时治理，相关端点仅允许 root/admin；见已知缺口 1。
- P3：pin 刷新双重记账（只计新增 selector 增量）、prewarm 并发上限事务内强制、
  integrity gauge 补齐全分布、delete 重放校验 op kind、GetSnapshot nil 防滞留、
  Legacy client 方法移除、4-in-6 注释修正、orphan 去重表上限。

未修复（有意）：`LocalInventoryV1` 无条件发布——能力语义是“List 响应携带观测
元数据”，该行为由 server 装配无条件保证（能力不支持时 RPC 返回 Unimplemented，
控制面 fail closed）。

## 已知缺口 / 未验证项

1. **node-pool ACL 数据模型未实现**：ADR-0037 的临时边界是所有 prewarm/coverage/pin
   端点 operator-only（root/admin），不是“project scope 已足够”。在独立 ACL ADR 和
   数据模型落地前不得放宽；coverage 也不得向普通 read key暴露节点拓扑。
2. **quarantine/delete 默认未启用**：image quarantine、grace rollback/finalize 已实现，
   但必须完成单节点恢复演练后才可设置 `FIREPAAS_LOCAL_GC_MODE=delete`。snapshot、
   LOCAL_RW、不可重建 DATASET_RO 永不进入自动物理删除 allowlist。
3. **scrub 默认未启用**：snapshot scrub、revision CAS 与预算调度已实现；上线前必须先取得
   IO 成本证据再设置 `FIREPAAS_SCRUB_ENABLED=true`。sealed DATASET_RO 的安全内容 scrub
   仍受 hypeman block-volume 能力限制，当前最多 METADATA_VERIFIED。
4. **双 compute 节点场景未演练**（leader handover、node loss 双节点、磁盘水位、72h soak）：
   单机实验室不可覆盖；v1.4-plan §10 版本级验收项。
5. **prewarm 并发/配额上限为 env 默认值**（未进 projects 治理表）：plan 未指定权威来源，
   采用保守默认 + env 覆盖；后续如需 per-project 配额再入 governance API。
6. **coverage 只统计 healthy 非 draining 节点**：与调度硬约束一致；label 级硬约束
   （arch 等）未纳入 eligible 判定（plan 中"满足部署硬约束"的完整实现需 deployment 上下文）。
7. **e2e-v13-volume 脚本第 6 节按 v1.4 语义更新**（overlay 不广告 + 明确拒绝），
   与仓库内旧描述（"发布 overlay 能力"）不一致——以 v1.4 plan 与 ADR-0030 现状为准。

## 回滚

1. 先把所有节点/控制面 `FIREPAAS_LOCAL_GC_MODE=off`，停止新 prewarm/pin 和任何 scrub
   调度；确认配置实际生效。等待在途 prewarm target 终态，并检查 `local_scrub_jobs`、
   `local_gc_claims`。CLAIMED/QUARANTINED 必须先 ABORT/ROLLBACK；若无法回滚则停止
   二进制回滚并人工核对。
2. 再回滚二进制。migration 0027～0030 是新增表/列，保留数据且不执行 down migration；
   旧二进制忽略即可。已 finalize 的可重建 cache 只能从原来源重拉，二进制回滚不能恢复
   node-local 内容。
- proto：仅新增响应字段，旧控制面读新 agent 响应（多字段）安全；新控制面读旧 agent
  （complete=false）只会得到 UNKNOWN，不触发 MISSING/LOST/删除。
- prewarm/pin 端点随旧二进制下线；operations 表遗留 image_prewarm 行可能被旧
  controller 作为未知 kind 标记 FAILED，所以必须先停止受理并让队列有界清空。pin 事实
  保留到 expiry；回滚期间保持 local GC off。
