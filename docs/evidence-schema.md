# HA validation evidence schema

These assets produce **test evidence**, not a GA or production-acceptance claim. A run is valid only when the archive contains a clean Git commit, redacted configuration copies, topology inventory, checksums, raw observations, and every required result with `"result": "PASS"`.

## Required archive entries

- `manifest.json`: schema `1.0`, UTC capture time, run ID, Git commit, runner, and non-secret topology environment.
- `topology.txt`: operator-maintained host roles/addresses and software versions; never passwords, tokens, private keys, or full secret-bearing configuration.
- `config/`: only reviewed non-secret deployed configuration files.
- `SHA256SUMS` and `ARCHIVE-SHA256SUMS`: integrity checks.
- `events.jsonl`: UTC fault-injection events.
- raw API/query/probe output and a result JSON for each executed gate.

## Result JSON

Every gate result has `schema_version` when generated by an evaluator where applicable, `result` (`PASS` or `FAIL`), measured timings, and evidence. Missing evidence, malformed JSON, a non-PASS dependency, a dirty source tree, or missing topology/config input is a failure. `archive-run.sh` refuses to archive non-PASS results.

## Observation JSONL

Each line is one JSON object with a non-empty `timestamp` plus numeric metric fields named by `docs/slo-spec.yaml` (for example `node_failover_seconds`). Every observation must contain the timestamp and every metric required by every evaluated objective. A missing metric/timestamp, malformed value, or insufficient sample count fails SLO evaluation; it is never treated as zero.
