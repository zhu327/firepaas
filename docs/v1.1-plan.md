# firepaas:v1.1 计划

> 状态:执行草案 v1(2026-08-28)。范围来自对 `docs/fp.md`(另一份独立规划:WireGuard
> mesh + per-org IPv6 6PN 路线)与现有架构/实现的逐项对照评审;网络方向裁决见
> [ADR-0016](adr/0016-network-stays-l3-edge-routed.md)。本计划不推翻 MVP 已冻结的
> 契约与不变原则,只做本文列明的增量扩展;任何实现以 [architecture.md](architecture.md)
> 与 ADR 为准。

## 1. 定位与目标

MVP(M0–M5,单机折叠实验室形态)已交付内部生产就绪闭环。v1.1 的目标:

1. 补齐 fly.io 形态中缺失且经评审确认高价值的四块:
   - **完整 scale-to-zero**(空闲自动 standby,关闭 mvp-plan 记录的 v1.1 idle 检测遗留);
   - **镜像缓存亲和与部署预取**(改善未缓存冷启动 p95 7.6s 的实测短板);
   - **edge 流量语义**(实例标识响应头、调试钉扎、并发控制、least-inflight 选择);
   - **节点排水驱离**(零停机节点维护/升级);
2. 完成一项已列入 roadmap 的契约扩展:**多端口 services 模型**;
3. 打包小项:rolling batch 发布策略、per-VM 指标直抓;
4. 重申并关闭可关闭的 DEFERRED 遗留项(§7)。

排期基线:**1–2 人约 7–10 周**(单机实验室;多节点真实放置/反亲和/多 edge 验收仍按
DEFERRED-MULTI-NODE 惯例单独标注)。

## 3. 工作包

### V1.1-A:scale-to-zero 完整化(auto-standby 集成)

**ADR**:[ADR-0017](adr/0017-autostandby-idle-detection.md)。**依赖**:无(M4.5 已交付唤醒侧)。**预估**:1–1.5 周。

**目标**:空闲 app 自动 standby(释放 VMM 内存),来流量自动唤醒——zero 新协议,补齐
M4 显式 pause API + autoresume 之外的自动判定侧。

**已从代码验证的现状**(设计依据):

- health worker 对非 RUNNING 实例跳过探针并冻结最后 readiness(`internal/agent/health`)→
  standby 实例保留 READY 投影,仍在 route backends,流量可唤醒(与 M4.5 语义同构);
- reconcile 对 PAUSED 不重建(`agentStateUsable` 含 PAUSED);
- hypeman `lib/autostandby`:per-instance `Policy{Enabled, IdleTimeout,
  IgnoreSourceCIDRs, IgnoreDestinationPorts}`(Create 时下发),conntrack netlink 事件
  驱动,SYN_SENT 计为活动(天然 wake-on-traffic 友好),idle 计时持久化跨重启;
- agentd 以 root 运行,满足 conntrack 访问要求。

**工作项**:

1. agentd 装配 autostandby Controller:firepaas 侧 InstanceStore 适配器(参照 hypeman
   `lib/providers/auto_standby_linux.go` 的 store 模式自写——providers 版 import
   `cmd/api/config`,不可直接复用)+ `ConntrackSource` + 生命周期事件订阅;
2. proto:`MachineSpec.auto_standby`(enabled + idle_timeout_seconds);deployment spec
   增加 `auto_standby` 策略字段(改策略 = 新 deployment,走既有 rollout 语义);
   create 时翻译为 `CreateInstanceRequest.AutoStandby`;
3. **探针流量排除**:host 侧 readiness 探针(slot IP:port)会被 conntrack 记为入站
   活动,不清闲则永不 standby——必须把探针源段注入 `IgnoreSourceCIDRs`(slot 网关段);
4. **发布门控调整**:PREPARING 期间新代副本无真实流量,idle 到点会 standby;CUTOVER
   门控(RUNNING+READY)扩展为接受 `PAUSED 且冻结 readiness=READY/UNCONFIGURED`
   (首个请求承担唤醒延迟,在 autoresume SLO <5s 内);
5. metrics/事件:standby 触发、唤醒耗时计数;e2e 断言。

**验收**:

- `auto_standby` app 空闲 idle_timeout 后:PG observed=PAUSED、VMM 进程归零(内存释放);
- 后续 curl 首请求唤醒,200 返回且延迟 <5s(含 restore);
- 50 轮 idle→standby→唤醒 无 netns/TAP/firecracker 残留;
- 无策略 app(默认关闭)行为与 M5 完全一致(回归)。

### V1.1-B:镜像缓存亲和与部署预取

**ADR**:[ADR-0018](adr/0018-image-affinity-and-prefetch.md)。**依赖**:无。**预估**:1–1.5 周。

**工作项**:

1. `ServiceInfoResponse` 增加 `cached_image_digests`(repeated string,LRU 序、截断
   上限,agent 由 ListImages 派生);PG `nodes` 增加 `image_cache jsonb`,nodemanager
   20s sync 落库;
2. scheduler:`Request` 增加 `ImageDigest`;score 增加
   `WeightImage · imageMiss(n, digest)`(在缓存=0,不在=1;soft 罚项,不做硬过滤);
   默认 `WeightImage=0.5`,配置化(与 R/K/α 同一配置面);
3. 部署预取:rollout 创建后 PREPARING 前,向 top-K 候选节点异步 `PullImage`(digest)。
   失败/超时不阻塞 rollout(记录调度事件);尊重节点镜像 LRU 预算与磁盘水位
   (capacity-model 既有约束);
4. 镜像 digest 解析已有(imagepolicy/digest-pinned),prefetch 复用同一引用。

**验收**:

- 未缓存镜像部署:副本落点优先命中已 prefetch 节点;调度事件含 image miss 罚项记录;
- e2e 计时:预取生效后副本 READY 时长较冷拉取路径显著下降(记录基线对比);
- 节点磁盘水位下 prefetch 不突破预算(imageretention GC 语义不回退)。

### V1.1-C:edge 流量语义(标识/钉扎/并发控制/least-inflight)

**ADR**:[ADR-0019](adr/0019-instance-identity-and-debug-pinning.md)、
[ADR-0020](adr/0020-edge-concurrency-and-least-inflight.md)。**依赖**:无。**预估**:1.5–2 周。

**工作项**:

1. 响应头 `X-Firepaas-Machine-ID`(命中 backend 的 machine id;serve-stale 与 403
   重试路径同样覆盖);
2. 请求钉扎 `X-Firepaas-Pin-Machine: <machine_id>`:命中 eligible 集合 → 直选并
   优先于选择算法;不在集合 → 404(显式失败,与 503 区分);
3. per-machine inflight 计数(edge 内存,请求生命周期含流式/WS);
4. 后端选择从 round-robin 计数器改为 **least-inflight + 随机抖动**;hard 并发上限
   (`FIREPAAS_EDGE_HARD_CONCURRENCY`,默认 256):最闲者仍超限 → 503 + Retry-After;
   soft 语义由 least-inflight 天然承担(文档化,app 级配置留 v1.2);
5. metrics:`firepaas_edge_backend_inflight`(per machine gauge)、hard 拒绝、钉扎命中
   计数;多 edge 各自计数(per-edge 语义,与 token 缓存同形态,文档标注局限)。

**验收**:

- 慢副本场景(单副本注入延迟):流量显著偏移到快副本(断言分配比例);
- 钉扎请求 100% 命中指定 machine(响应头校验);钉错 id → 404;
- 压测触发 hard 上限 → 503 + 计数器正确;低负载时分布与 M4 行为无回退;
- WS/SSE 长连接期间 inflight 持续计数,断开后归零(无泄漏)。

### V1.1-D:节点排水驱离(drain evacuate)

**ADR**:[ADR-0021](adr/0021-drain-evacuate.md)。**依赖**:B(亲和加速重建)、C(inflight
观测)。**预估**:1 周。

**工作项**:

1. `POST /v1/nodes/{id}/drain` 扩展 body `{evacuate: bool}`(默认 false,保持 M5.5
   兼容语义);
2. controller evacuate 编排:对节点上每个 machine 逐个(concurrency=1):触发换代
   重建(复用 R3 机制,新 execution;调度天然避开 draining 节点)→ 新代 READY 且
   切流 → 旧实例 delete → 下一个;standby 实例直接重建(不先唤醒);
3. 与 rollout 互斥:app 有 active rollout 时等待/跳过(复用 rolloutHoldsRecreate
   语义,记录事件);
4. 完成判定:节点 fp machine 归零 → 事件与状态可置 maintenance;
5. `scripts/lab/upgrade-agentd.sh` 升级为 evacuate 版(零停机升级演练);
   runbook-node-replacement 更新。

**验收**:

- drain+evacuate 全程并发 curl 0 失败(副本 ≥2);
- 单副本 app evacuate 期间存在短暂窗口:文档化"建议副本 ≥2 时执行",断言重建后
  READY 且路由恢复;
- evacuate 与 active rollout 组合不破坏 ADR-0015 单 rollout 互斥。

### V1.1-E:多端口 services 模型

**ADR**:[ADR-0022](adr/0022-multiport-services.md)。**依赖**:建议在 C 之后(契约
变更最大,放最后)。**预估**:2–3 周。

**工作项**:

1. 数据模型:`deployments.port` → `services jsonb`(`[{name, internal_port}]`),
   迁移把存量单 port 转一条 service;
2. proto:`MachineSpec.services`(repeated);保留 `network.ingress_port` 兼容读
   (单端口行为不变);
3. catalog:hostidx 从"每 hostname 单活跃端口"演进为 hostname→port 集合;
   `route:{hostname}:{port}` 每 service 一条,backend `AppPort` = 该 service 的
   internal_port;
4. edge:可选监听附加端口段(`FIREPAAS_EDGE_EXTRA_PORTS`,默认关闭);按
   (hostname, 请求端口) 查路由;转发时带 `X-Firepaas-App-Port` 请求头;
5. agent proxy:端口白名单从单一 ingress port 扩为 services 集合(头缺失 = 旧行为,
   向后兼容);
6. readiness:v1.1 每 machine 仍单探针(主 service),附加 service 跟随主 service
   的 readiness(ADR-0022 记录为限制,v1.2 再独立);
7. API/CLI:`deploy --port name=8081` 重复声明;fpctl status 展示 services。

**验收**:

- 双端口 app(如 HTTP + 第二 HTTP)经 edge 两个端口分别路由到同一批副本;
- 单端口存量 app 无回归(e2e-m3/m4 全绿);
- 未声明端口访问 → 404;proxy 拒绝未声明端口(403/502)。

### V1.1-F:打包小项

**依赖**:无。**预估**:0.5–1 周。

1. **rolling batch 发布策略**:`deployments.strategy`(默认 `bluegreen`=现状全量
   切换;`rolling`:batch = max(1, 25%·目标副本) 逐批 建新→READY→切流→回收同批
   旧代)。ADR-0015 状态机扩展,不新增状态,只增加批次推进器;
2. **agent/per-VM 指标直抓**:Prometheus 通过 Nomad 服务发现抓取正式
   `firepaas-agentd-metrics` 的 `:9464`；agent 默认 loopback 绑定，正式 job
   显式非 loopback bind 时由网络 ACL 限制为可信 observability 网段（端点无 HTTP
   鉴权）。交付 per-VM CPU/RSS 与 agent 指标；**slot 网卡网络指标 DEFERRED**，
   在具备正确 slot netns TAP 采集前不得以 0 值或文档宣称完成。Grafana 仅追加已
   实现维度的 app/machine 面板。原 v1.1 的"per-VM usage 管道"方案废止：idle
   检测动机已被 V1.1-A 取代，残余观测动机由直抓覆盖；
3. 遗留项处置复核(§7)。

**验收**:

- rolling 策略发布期间并发请求 0 失败、任意时刻可用副本 ≥1;失败回滚路径与
  bluegreen 一致;
- Prometheus 可经受 ACL 约束的 Nomad service discovery 抓取 agent 指标；Grafana
  可按 app/machine 下钻已实现的 per-VM CPU/内存指标。slot 网卡网络维度明确
  DEFERRED，不作为本版验收项。

## 6. 风险与降级

| 触发 | 决策 |
|---|---|
| auto-standby 与 conntrack 在 slot NAT 下的判定不准(误判活跃/空闲) | e2e 加断言;不准则回退为显式 pause API + 定时任务(控制面侧 idle 判定),不阻塞其余工作包 |
| 探针排除后仍有第三方探测流量打进 slot | 文档化 IgnoreSourceCIDRs/IgnoreDestinationPorts 语义;必要时 app 级关闭 auto_standby |
| CUTOVER 接受 PAUSED 导致首请求延迟超 SLO | 门控回退为"PREPARING 完成前禁用策略,切流后启用"(agent UpdateInstance 支持热替换策略) |
| prefetch 加剧节点磁盘压力 | 预取仅 top-K、尊重水位;必要时退化为仅亲和打分不预取 |
| 多端口 hostidx 演进引入 Redis 投影不一致 | controller 按 hostname 将权威完整端口集交给 Redis Lua 原子替换（含删除移除 service 的 route）；不做逐端口 RMW，FLUSHALL 后由重建恢复 |
| evacuate 与 rollout 组合状态机超预期 | evacuate 期间遇到 active rollout 即暂停并等待(不做并发编排),复杂组合明确延后 |
| rolling batch 与 readiness 抖动共振 | batch 推进以 READY 稳定 N 个探针周期为门(复用 M3 语义) |
