# v1.3 implementation notes

> Document role: current implementation record for the scope in [v1.3-plan.md](v1.3-plan.md). It does not declare release acceptance. The original dated execution log is retained in [archive/milestones](archive/milestones/2026-08-31-v13-implementation.md).

## Delivered paths

- Egress policy and audit (ADR-0027), including capability gating and focused e2e coverage.
- Snapshot resources, checkpoint, retention, restricted fork and filesystem rescue (ADR-0028).
- Node-local `LOCAL_RW` volume ownership and fencing (ADR-0029).
- `DATASET_RO` import/seal and associated validation paths have subsequently been implemented and tested in focused scripts.

## Deliberately unavailable

Writable per-execution CoW from ADR-0030 is not advertised. Requests fail closed until the hypeman volume adapter, accounting, lifecycle cleanup and acceptance evidence are complete. The readonly dataset base must never be described as writable or durable overlay storage.

## Validation boundary

Focused scripts exist for egress, snapshot and volume behavior. A passing focused script establishes only that scenario in the tested environment. The v1.3 plan's predecessor, multi-node, destructive and long-duration gates remain separate release requirements; consult the [GA observation scorecard](ga-observation-scorecard.md) rather than inferring release readiness from implementation checkboxes.

## Historical record correction

The original 2026-08-31 execution record checked the v1.3.3 slice while also saying DATASET_RO import was only a schema framework. That checkbox represented work-session completion, not version acceptance. Later implementation and tests supersede the framework-only statement, while CoW remains unavailable as described above.
