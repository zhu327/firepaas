# firepaas v1.3 计划：受控网络与节点本地状态能力

> 状态：规划草案 v1（2026-08-28）。前置版本为 v1.2。v1.3 继续保持 PG 业务
> 权威、agent 运行态权威、Redis 可重建投影和 L3 edge-routed 网络；决策见
> ADR-0027～0030。

## 1. 版本定位

v1.3 在单集群内增加两类有边界的能力：

1. **受控网络**：域名/SNI egress policy、连接限制和租户可见审计；
2. **节点本地状态**：first-class snapshot、checkpoint、受限 fork、filesystem-only
   rescue、node-local volume 和只读 dataset CoW。

所有状态能力都必须向用户暴露 locality、durability 和 compatibility，不得把
node-local 能力包装成跨节点 HA。

排期基线：**2 人 14～18 周；1 人 20～28 周**。建议拆成 v1.3.0～v1.3.3
逐段发布，而不是在一个长分支中同时建设网络、快照和卷。

## 2. 入口门禁

- v1.2 one-shot secret、capability、TTL/restart、runtime streams 已完成 72h soak；
- v1.1 单集群 HA scorecard 保持 PASS；
- snapshot compatibility key 已由 capability 契约稳定表达；
- hypeman snapshot/fork/volume 所需 API 已进入不可变 tag；
- 有至少一个真实域名 allowlist 用户、checkpoint/fork 用户和 dataset/RW volume
  用户故事，否则对应能力降为实验 feature flag；
- 节点磁盘容量、快照预算和 GC 水位已有实测模型。

## 3. 范围总表

## 4. V1.3-A：域名 Egress Policy 与审计

**ADR：** [ADR-0027](adr/0027-egress-policy-and-audit.md)。

### 策略模型

```text
mode: unrestricted | deny_all | allowlist
allowed_cidrs[]
denied_cidrs[]
allowed_domains[]       # exact 或 *.example.com
max_tcp_connections
policy_generation
audit_mode: denied | all
```

- policy 属于不可变 deployment；修改策略产生 rollout；
- CIDR 继续由 nftables 执行；TCP/80 检查 HTTP Host，TCP/443 检查 TLS ClientHello
  SNI；不做 TLS 解密；
- 无 Host/SNI、ECH、非 80/443 TCP 和 UDP 不能声称受域名规则保护：只按 CIDR
  判断；allowlist-only 模式默认拒绝；
- agent 使用可信 resolver 解析规范化 Host/SNI，忽略 guest 原始目标 IP，并只连接
  本次可信解析且通过保留段检查的 A/AAAA 集合；若保留原始目标，则必须验证其属于
  该集合；处理完整 CNAME 链、受限 TTL 和失败拒绝，避免 guest DNS、`/etc/hosts`
  和 rebinding；
- 规则完整替换并带 generation fencing；失败保持旧策略，不允许半更新；
- per-execution TCP 连接限额保护 FD/conntrack。

### 审计

连接决策记录 project/app/machine/execution、policy generation、协议、端口、Host/SNI、
resolved IP、allow/deny、match type 和 reason。禁止记录 URL path/query/header/body 和
credential。高频事件写日志 sink，PG 只保存策略变更和拒绝摘要；域名不得作为
Prometheus label。

### 验收

- exact/wildcard/case-insensitive、CIDR 优先级矩阵全绿；
- 无 SNI、ECH、非标准端口、UDP、IPv6 行为有明确测试；
- DNS rebinding 和 metadata/private IP 绕过失败；
- pause/resume、agent restart、rollout 后策略保持；
- 10k 并发连接下延迟、CPU、FD、conntrack 在预算内；
- 审计 project 隔离且不含敏感正文。

## 5. V1.3-B：Snapshot 资源、Checkpoint、压缩与保留

**ADR：** [ADR-0028](adr/0028-snapshot-checkpoint-fork-and-rescue.md)。

### 数据模型

新增 PG `snapshots`：

```text
id, project_id, source_machine_id, source_execution_id,
kind(MEMORY|FILESYSTEM), status, node_id, compatibility_key,
size_bytes, checksum, compression, compression_state,
retention_class, expires_at, created_at
```

PG 只拥有快照元数据和操作事实；v1.3 artifact 仍在 agent 本地。API 必须返回：

- `locality=node-local`；
- `origin_node_id`；
- `durability=best-effort`；
- compatibility key；
- 明确状态机：`CREATING → READY → DELETING → DELETED`，节点暂时不可达时
  `READY → UNAVAILABLE ↔ READY`；只有节点退役、人工确认或 agent inventory
  权威证明文件不存在时才进入不可逆 `LOST`。压缩是正交子状态，不能把半成品置 READY。

### Checkpoint

- checkpoint = `pause → capture → resume source`；源 machine ID/execution 不变；
- 请求必须带 operation fencing，重试不产生重复快照；
- capture 失败必须恢复源 VM，无法恢复则转明确终态并告警；
- writable volume attachment 时拒绝 memory checkpoint；
- 遵循 ADR-0024：接收过 secret 的 execution 禁止 memory checkpoint/fork；只允许
  filesystem-only checkpoint，且平台注入路径位于 tmpfs、不写 rootfs。应用主动复制
  secret 到持久文件属于用户责任；恢复时平台重新授权交付。

### 压缩与 retention

- 支持 none/zstd/lz4 capability；默认 hot snapshot 不立即压缩；
- `compression_delay` 后异步压缩；restore 可取消或等待压缩，不能读半成品；
- schedule 使用 deterministic jitter，宕机后跳到未来周期，不补跑全部历史；
- `max_count/max_age` 只清理相同 schedule 产生的 snapshot，不删除手工 checkpoint；
- 删除前检查 restore/fork 引用，所有临时文件可回收。

## 6. V1.3-C：受限 Fork 与 Filesystem-only Rescue

### Fork

- fork 只创建同 project 的 `EPHEMERAL/DEBUG` machine；
- 默认无 public route，TTL 必填；新 machine/execution/slot/credential/ledger；
- 不继承 secret 值；secret refs 必须显式选择并重新授权；
- 不继承 LOCAL_RW volume；DATASET_RO 可按规则重新 attach；
- fork 不直接加入 production route，也不绕过 app rollout；若要生产化，必须以
  snapshot 为 deployment source 走新 rollout；
- v1.3 只支持 origin node fork，资源必须纳入 reservation 和 agent 硬准入。

### Rescue

API 提供 `restore_mode=memory|filesystem|auto`：

- `memory` 必须匹配完整 compatibility key；
- `filesystem` 忽略内存/device state，从 rootfs 冷启动；
- `auto` 只在明确的兼容性错误上降级，不能吞掉 checksum、损坏或权限错误；
- filesystem checkpoint 前经 guest channel 执行 sync/fsfreeze，所有成功、失败、
  timeout、cancel 路径都必须 thaw；
- `filesystem_consistency=clean|crash-consistent` 显式返回；不安全 memory snapshot
  默认不能被当作 clean filesystem snapshot。

### 验收

- running checkpoint 后源持续服务且 execution 不变；
- fork 身份、网络、secret 和 volume 隔离；
- 不兼容节点 memory restore 明确拒绝，filesystem rescue 可成功；
- freeze 后任意故障不使 guest 永久 frozen；
- 100～1000 次 checkpoint/fork 后 VMM、TAP、netns、FD 和临时文件归零；
- origin node 丢失后 API 明确报告不可用，不在其他节点静默创建空状态。

## 7. V1.3-D：Node-local Volume 控制面

**ADR：** [ADR-0029](adr/0029-node-local-volume-ownership.md)。

### 数据模型

```text
volumes(id, project_id, name, node_id, size_bytes, mode,
        state, content_digest, created_at, deleted_at)
volume_attachments(volume_id, machine_id, execution_id,
                   mount_path, readonly, overlay_size_bytes, status)
```

本工作包只交付 `LOCAL_RW`：单写 attach、硬钉 node；节点丢失后 `UNAVAILABLE`，
不得在别处创建空同名卷；有此卷的 machine 不执行现有 delete-then-recreate evacuate。
通用 schema 预留 mode，但 `DATASET_RO` 在 V1.3-E 才启用。

attachment 必须绑定 execution；旧 execution 的 detach/attach 不得影响新代。volume
locality 在资源过滤和反亲和之前执行，冲突时 locality 胜出并记录降级事件。

LOCAL_RW v1.3-D 只支持空卷创建和已有本地卷登记，不开放 archive 导入；导入属于
DATASET_RO 的不可变 seal 流程。

## 8. V1.3-E：Readonly Dataset + Per-execution CoW

**ADR：** [ADR-0030](adr/0030-readonly-dataset-cow.md)。

- 控制面签发短时导入 token/预签 URL，文件不经过主 API；agent 流式下载 tar.gz，
  验证 digest、总大小和文件数，并防 archive traversal、symlink escape、device/FIFO
  和解压炸弹；import 完成并原子 seal 后才允许 attach；
- dataset base 以 digest 标识且不可变；
- 多 machine 共享只读 base；可选 per-execution writable CoW overlay；
- overlay 默认随 execution 删除，不构成持久卷；
- fork 获得独立 overlay；checkpoint 默认不包含 dataset base，只记录 digest；
- base/overlay 分别记账，GC 以 attachment、snapshot 和 in-flight operation 为 roots；
- 无本地副本时 v1.3 不自动跨节点复制，只返回无候选或由运维预热。

### 验收

- LOCAL_RW 同时只能有一个 active attachment；
- DATASET_RO 多挂载，overlay 写入互不可见且 base digest 不变；
- agent/leader crash 不产生双 attachment；
- node loss 后状态明确，不跨节点空建；
- archive 恶意输入不能逃逸；
- machine 删除后 attachment/overlay 收敛，容量记账恢复。

## 9. Future consideration：Credential Broker

Credential broker 不属于 v1.3 承诺范围。只有 one-shot secret 稳定且出现明确需求后，
才单独立项和编写 ADR，覆盖 destination canonicalization、redirect、DNS/SNI 绑定、
token audience、撤销、审计及平台代理 CA/MITM 信任边界。在此之前继续使用 one-shot
file secret，禁止把 hypeman persisted-env 包装为安全 broker。

## 10. 非目标

- 跨节点 snapshot/volume 复制和 durability SLA；
- RW 多挂载、热挂载、在线 resize、volume snapshot；
- fork 自动进入 production backend；
- writable volume 的 memory checkpoint；
- 在线 VM 热迁移；
- TLS MITM、DLP、HTTP body inspection、UDP 域名识别；
- multi-cluster；Dockerfile build；UFFD；balloon；GPU；
- overlay/6PN/WireGuard/service mesh。

## 11. 发布切片和依赖

```text
v1.3.0  Egress policy + denied audit
v1.3.1  Snapshot resource + checkpoint + retention
v1.3.2  Restricted fork + filesystem rescue
```

A 与 B 可在对应 ADR 转为“已接受”且所需旧 ADR 已同步修订后并行；C 依赖 B；
D 可与 C 并行；E 依赖 D。共享 proto、迁移和 controller 状态机变更必须串行合并。

- 文档明确 node-local 状态在节点永久故障后的数据丢失边界。

## 13. 风险与降级

| 风险 | 决策 |
|---|---|
| SNI 代理影响延迟或兼容性 | per-deployment feature flag；退回 CIDR-only，不虚假宣称域名隔离 |
| ECH/无 SNI 绕过 | allowlist 模式拒绝；不做静默放行 |
| checkpoint 无法可靠恢复源 VM | checkpoint 标记失败并告警；不发布 snapshot；必要时暂停该 capability |
| filesystem freeze 无法保证 thaw | watchdog + defer thaw；失败时禁止生成 clean snapshot |
| fork 和 app rollout 语义混杂 | fork 永远是独立 debug machine，不写 production route |
| LOCAL_RW 阻塞 evacuate | fail closed，要求显式 detach/data-loss 决策 |
| dataset 跨节点需求膨胀 | v1.3 只本地预热；跨节点 content plane 进入 v2 |
